# v0.6.1 中文版隔离升级测试报告

日期：2026-10-14（Asia/Shanghai）

> 本报告记录隔离试验当时的状态。后续 v0.6.1-cn.1 正式适配以 Windows 核心使用为验收范围，参见 [发布说明](../releases/v0.6.1-cn.1.md)。

## 结论

隔离升级试验完成。保留中文分词、显式初始化和双库架构后，核心兼容性、真实 MCP 流程及隔离测试通过。试验版可以继续作为升级候选，但本次不等同于完整发布验收：文件符号链接权限、竞态检测和非 Windows 实机运行仍有验证缺口。

现用版本仍是 v0.4.3-cn.1，未替换可执行文件、wrapper 或客户端配置。主工作区保持干净。本次没有提交、推送、发布，也没有连接真实 Hub 执行同步。

## 合入与适配内容

1. 合入 v0.4.4～v0.6.1 的元数据编辑、过滤、到期检查、知识包、锁文件、多层检索、列表解析、来源保护及 Hub 同步状态持久化。
2. 保留 `gse` 中文搜索分词、编译时嵌入词典、显式 `okf_init()`，以及无参数 `okf init` 默认创建 `knowledge/`。
3. 将中文定制迁移到上游重构后的 `pkg/okf` 和 `internal/cli`，保留原 wrapper 路径与参数。
4. `OKF_MCP_ROOT` 显式设置时，MCP 搜索仅接受省略 scope、`bundle` 或 `project`；`okf_show` 仅读取本库 ID。工具 schema 与该边界一致。跨层 scope、URI 和外部 bundle 参数不能扩大访问范围。
5. 缺库时 MCP 可握手，查询报错，不自动初始化或静默返回其他层的数据。独立 MCP 的多层读取仍要求绑定库可加载；CLI 保留上游多层能力。
6. Windows 实测发现 `filepath.EvalSymlinks` 不展开部分 junction。改用文件句柄最终路径解析，应用于库加载、MCP 边界及写入路径。复用已有 `x/sys/windows` 模块，未新增模块种类。
7. 用 OKF 引擎将隔离知识库的 MCP code_refs 从 cmd/okf/mcp.go 更新为 pkg/okf/mcp.go，消除代码迁移漂移警告。该旧概念正文中的完整 frontmatter 示例触发保存防注入规则，已在副本中移除示例分隔符，保留字段内容；没有放宽安全检查。
8. 修正上游恢复测试写死 `/` 路径分隔符导致的 Windows 误报，断言前归一化路径。

## 对现有结构的影响

- 项目 `knowledge/` 和全局 `~/.config/agent-memory/knowledge` 均可保持原路径。
- `okf-project`、`okf-global` 服务名称和 wrapper 均可保留；本次试验没有要求修改客户端配置。
- 核心数据仍为 OKF v0.2。本次验证了旧版创建 → 新版读取 / 更新 → 旧版读取和严格校验；这不代表新版所有列表元数据能被旧版等价理解。
- 搜索排序采用新的 BM25 逻辑，评分数值和顺序可能改变；中文召回回归已通过，不保证所有历史查询排序完全相同。
- 新版默认的跨层功能受到双库隔离模式限制；如将来启用外部知识包或跨库联合读取，需要单独决定边界。
- `--filter` 必须使用 `tags`、`code_refs`、`description` 正式字段名；旧别名不兼容。

## 尚未覆盖与建议

1. 在支持文件符号链接且具备 cgo 的环境中补跑无排除的完整测试、`--agents` 校验和 race。
2. 在 Linux / macOS 实际运行测试；交叉编译仅证明可构建。
3. Hub、Registry 的测试使用上游本地模拟和单元测试；本次未使用真实账号或远端服务，未做实际云同步 / 下载联调。
4. 现有客户端尚未切换，不把真实 stdio 测试等同于四套客户端全部完成升级验收。

建议保留此工作树作为升级候选，补齐发布验证后再决定切换现用程序。当前试验结论是：保持原双库结构升级可行，但需要本报告列出的中文与隔离适配，不能直接换成上游原版 exe。
