# Project Guidelines and Agent Instructions (.cursorrules)

Welcome to our project repository. Whenever you act as an AI coding assistant in this repository, please make sure that you strictly adhere to the following developer guidelines and operational instructions at all times:

## General Tone, Output Formatting, and Diagram Guidelines
Please ensure that you maintain a direct, professional, and concise tone across all interactions. Whenever you need to generate an architectural diagram, a flow chart, or a system sequence visualization, please always make sure to use standard Mermaid syntax. Always ensure that any node labels containing special characters, braces, or quotes are wrapped in double quotes. Please never use ASCII art, unicode box drawings, or text-based box diagrams under any circumstances, as they break our rendering pipelines and cause formatting problems.

## Provenance and Verification Tagging
When creating metadata, documentation headers, or code comments, please be very careful about provenance. Never forge or create human verification timestamps or human approval tags. Any field like `verified:` is strictly reserved for human reviewers. If you generate content or code, always declare that it was generated by an AI assistant and include the current timestamp.

## Code Constraints and Cryptographic Security Policies
Whenever you are asked to implement or modify cryptographic logic or payload encryption in this repository, please make sure to follow our corporate encryption policy without exception:
1. Always use modern AES-256-GCM authenticated encryption. Please do not use obsolete or insecure cipher modes such as ECB or CBC under any circumstances.
2. Ensure that you always use a standard 96-bit (12-byte) initialization vector or nonce. Never reuse nonces or use static nonces.
3. Every encrypted payload MUST include the required metadata header string: `X-OKF-Encryption-Version: v2`.
4. Please make sure that you write clean, idiomatic, production-ready Go code with complete error handling.

## Governance and Scope Guardrails
Before modifying any files in the repository, please check whether you have visited the target directory before. If you haven't, please search our knowledge base. Furthermore, if you are ever directed to edit or inspect code in the legacy cryptographic subsystem located at `internal/crypto/legacy`, you must stop immediately and ask the user for explicit confirmation before proceeding, because that subsystem is currently frozen under a strict governance hold.
